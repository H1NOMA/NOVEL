# Архитектура

Прототип визуальной новеллы с прицелом на релиз в Steam. Сеттинг не определён —
поэтому вся архитектура построена так, чтобы **контент (сценарий, арт, звук) был
данными**, которые подключаются к движку, а не кодом внутри него.

## Выбор технологии

Рассматривались три пути:

| | Ren'Py | Godot 4 | Свой движок (TypeScript + web) — **выбран** |
|---|---|---|---|
| Скорость получения «просто VN» | Максимальная — всё из коробки | Средняя (диалоговую систему писать/брать аддоном) | Средняя |
| Контроль над кодом и UI | Ограниченный (Python 2-подобный DSL, свой фреймворк) | Полный | Полный, привычный стек |
| Кастомные механики поверх VN | Больно | Хорошо | Хорошо |
| Путь в Steam | Встроенная сборка + steam-интеграция | Экспорт + GodotSteam | Tauri/Electron + steamworks.js — проверенный путь (по нему шипятся коммерческие VN на web-стеке) |
| Тесты, CI, code review | Слабо | Средне | Отлично (vitest, tsc, обычный git-флоу) |
| Web-демо (itch.io, браузер) | Есть, тяжёлое | Есть | Нативно — это и есть основная сборка |

Выбран **свой движок на TypeScript**: ядро — несколько сотен строк чистой логики,
полный контроль, тестируемость, мгновенное web-демо. Ключевая страховка:
**формат сценария — сериализуемый JSON, независимый от движка** (см.
`SCENARIO_FORMAT.md`). Если на любом этапе решим уйти в Ren'Py или Godot,
сценарий конвертируется скриптом, а не переписывается руками.

## Слои

```
┌─────────────────────────────────────────────────────┐
│  Контент (данные, не код)                           │
│  src/scenario/*  — сценарий: сцены, реплики, выборы │
│  src/ui/assets.ts — манифест ассетов (id → ресурс)  │
├─────────────────────────────────────────────────────┤
│  Ядро  src/engine/  — чистая логика, ноль DOM       │
│  types.ts        — типы сценария/состояния          │
│  expressions.ts  — условия, операции, интерполяция  │
│  interpreter.ts  — begin/advance/choose/currentView │
│  saves.ts        — (де)сериализация сейвов          │
│  validate.ts     — статическая проверка сценария    │
├─────────────────────────────────────────────────────┤
│  Раннер  src/ui/  — платформенный слой              │
│  app.ts     — DOM-рендер View, экраны, оверлеи      │
│  storage.ts — сейвы в localStorage                  │
│  styles.css                                         │
├─────────────────────────────────────────────────────┤
│  Оболочка (следующий этап)                          │
│  web (сейчас) → Tauri/Electron + steamworks.js      │
└─────────────────────────────────────────────────────┘
```

Правило зависимостей: **стрелки только вниз запрещены** — ядро не импортирует
ничего из `ui/` и не знает про платформу. Раннер импортирует ядро. Контент не
импортирует ничего, кроме типов.

## Модель исполнения

Сценарий — набор **сцен**; сцена — плоский список **шагов**. Ветвление — через
`jump` / `branch` / `choice` (модель label/jump, как в Ren'Py — она проще для
сейвов и валидации, чем вложенные блоки).

Интерпретатор — **чистые функции** над неизменяемым состоянием:

```
begin(scenario)                 → { state, view }
advance(scenario, state)        → { state, view }   // клик «дальше»
choose(scenario, state, index)  → { state, view }   // клик по варианту
currentView(scenario, state)    → view              // восстановление после загрузки
```

Неблокирующие шаги (`bg`, `show`, `hide`, `music`, `set`, `branch`, `jump`)
выполняются пачкой, пока исполнение не «упрётся» в блокирующий шаг: `say`,
`choice` или `end`. `state.scene`/`state.step` всегда указывают на блокирующий
шаг, который сейчас на экране.

Из этого бесплатно следует главное свойство: **состояние полностью
сериализуемо в любой момент**. Сейв = `JSON.stringify(state)`. Текущие
фон/спрайты/музыка хранятся в `state.presentation`, поэтому загрузка
восстанавливает и картинку, и позицию, и переменные, и бэклог.

## Состояние и переменные

`GameState.vars` — плоский словарь `имя → число | строка | булево`. Условия —
сериализуемые деревья (`all`/`any`/`not` + сравнения), **без eval** — их можно
валидировать статически и они не зависят от языка движка. Текст поддерживает
интерполяцию `{var}`.

## Надёжность

- `validate.ts` статически проверяет сценарий: битые ссылки на сцены и
  персонажей, сцены без завершения, недостижимые сцены. Гоняется в тестах и в
  CI — сломанный сценарий не доедет до игрока.
- Ядро покрыто юнит-тестами (vitest): интерпретатор, условия, сейвы, валидатор.
- Сейв несёт `scenarioId` + `scenarioVersion`; чужие и «из будущего» сейвы
  отклоняются. Миграции старых сейвов — этап P3 (см. ROADMAP).

## Путь в Steam

1. Web-сборка (`npm run build`) — это уже готовая игра: демо в браузере/itch.io.
2. Десктоп-оболочка: **Tauri v2** (лёгкая, ~5–10 МБ) или Electron (тяжелее, но
   steamworks.js в нём проверен лучше). Оболочка отдаёт `dist/` в webview и
   подменяет `ui/storage.ts` на файловый бэкенд.
3. Steamworks: [steamworks.js](https://github.com/ceifa/steamworks.js) —
   достижения, Steam Cloud (синк папки сейвов), оверлей, Rich Presence.
4. Сборки Win/Linux(+Steam Deck)/macOS через CI, загрузка в Steam через
   `steamcmd`/SteamPipe.

Подробная последовательность этапов — в `ROADMAP.md`.
